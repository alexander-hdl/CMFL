# CMFL: как устроен репозиторий

Семейный проект: исследования для родителя (`research/`), задания для игр (`prompts/`) и браузерные приложения для сына 9 лет (`apps/`), которые публикуются как артефакты claude.ai и как автономный сайт на GitHub Pages. Язык всего, что видит пользователь, и всех документов — русский, с буквой «ё».

## Карта папок

| Папка | Что там | Кто меняет |
|---|---|---|
| `apps/<имя>/` | Одно приложение: `app.json`, страница (один HTML-файл), `icons/180.png` `192.png` `512.png`, `README.md`; у игр ещё `tests/` и `dev/` (журнал работы) | Сессия, которая работает над этим приложением |
| `tools/build_site.py` | Собирает сайт из `apps/*/app.json` в `docs/` | Только при изменении самой сборки |
| `tools/test_app.mjs` | Запускает автотесты приложения: `node tools/test_app.mjs <имя>` | Только при изменении самого запускателя |
| `.github/workflows/pages.yml` | Собирает и публикует сайт при пуше в `main` | Редко |
| `docs/` | Сгенерированный сайт. **Не коммитится** (в `.gitignore`), не правится руками | Никто |
| `prompts/` | Задания для Fable на новые игры и общие принципы учебных игр | Автор задания |
| `research/` | Обзоры исследований с пометками доказательности 🟢🟡 | Автор обзора |
| `README.md` | Корневой обзор: одна строка на приложение, ссылки на папки | Одна строка при добавлении приложения |

## Главное правило: приложение живёт в своей папке

Переезд в `apps/` сделан, чтобы параллельные ветки не конфликтовали. Поэтому:

1. Работая над одним приложением, меняйте только его папку `apps/<имя>/`. Общие файлы (`tools/`, корневой `README.md`, `prompts/README.md`) трогайте только если это и есть задача.
2. Новое приложение регистрируется **только своим `app.json`** (см. ниже). `tools/build_site.py` менять не нужно: он сам находит папки с `app.json`.
3. Сайт `docs/` не коммитится. Локально его собирает `python3 tools/build_site.py`, на GitHub — workflow при пуше в `main`. Если в PR есть изменения `docs/`, это ошибка.
4. Одна ветка и одна сессия на одно приложение. Корневой README при добавлении приложения получает одну строку в списке «Приложения» (раздел «План для сына») и ничего больше; подробное описание идёт в `apps/<имя>/README.md`.
5. Выходное имя файла на сайте (`out` в `app.json`) и префикс иконок (`icon`) после публикации не меняются: на них держатся ссылки, установленные на планшет иконки и кэш service worker.

## Формат страницы приложения

Страница пишется для артефакта claude.ai: **без** `<!doctype>`, `<html>`, `<head>`, `<body>`. Файл начинается с `<title>`, затем необязательные `<link>` на Google Fonts, `<style>`, разметка и один `<script>`. Сборка и запускатель тестов сами оборачивают её в документ. Всё в одном файле: без внешних картинок, звуков и библиотек; canvas и WebAudio рисуют и звучат процедурно. Прогресс хранится в `localStorage`, а при наличии `window.claude.use("db")` зеркалится в хранилище артефакта (образец: `attachDb` в `apps/oborona-tablicy/oborona-tablicy.html` или блок `store` в `apps/arena/trenazhery.html`). Функции ИИ работают только на claude.ai; текст, который это объясняет, на сайте подменяется через `rewords` в `app.json`.

## `app.json`

```json
{
  "name": "Оборона таблицы",          // полное имя (title страницы, манифест)
  "short": "Оборона",                 // имя под иконкой на экране «Домой»
  "source": "oborona-tablicy.html",   // файл страницы в этой папке
  "out": "oborona-tablicy.html",      // имя на сайте; не менять после публикации
  "color": "#17324a",                 // theme-color и фон иконки
  "icon": "tower",                    // префикс: на сайте будет icons/tower-192.png
  "order": 50,                        // место на главной (меньше — выше)
  "card": "Для сына: защита крепости, где оружие — таблица умножения",
  "title": "…",                       // необязательно: заголовок карточки, если отличается от name
  "artifact": "NUnVhvzy88WsXPZpf4yvSm", // необязательно: id артефакта claude.ai, ссылки на него станут относительными
  "rewords": [["текст в исходнике", "текст на сайте"]], // необязательно
  "tests": "tests"                    // необязательно: папка автотестов
}
```

Иконки: `icons/180.png`, `192.png`, `512.png` — одноцветный знак на фоне цвета `color`, как у остальных (см. `apps/*/icons/`). Сгенерировать можно скриптом на PIL, как сделано для башни в журнале «Обороны».

## Как добавить приложение

1. Создать `apps/<имя>/` с `app.json`, страницей, тремя иконками и `README.md` (что это, для кого, что тренирует, где исходник и тесты).
2. `python3 tools/build_site.py` и открыть `docs/index.html`: карточка на месте, страница открывается, в `docs/sw.js` она есть в `CORE`.
3. Если есть автотесты: `apps/<имя>/tests/*.mjs`, каждый экспортирует `register({ test, assert, eq })`; тест получает `{ page, errors, app, shot }`. Страница должна выставлять `window.OT` с функцией `state()` (отладочный интерфейс для тестов), иначе запускатель не дождётся загрузки.
4. Одна строка в корневом `README.md` в списке «Приложения».
5. Если игра сделана по заданию из `prompts/`, в начало файла задания добавить строку «Готово: игра лежит в `apps/<имя>/`».

## Учебные игры: принципы, которые нельзя нарушать

Из `prompts/README.md`: учебное действие и есть главная механика, а не викторина между уровнями; ошибку показывает мир, а не надпись «Неверно»; никаких сундуков, случайных наград, бонусов за вход, сгорающих серий, рекламы, покупок, бесконечного режима и таймеров в момент выбора; естественный конец сессии через 10–15 минут; слова с ошибками не показывать никогда; повторение с промежутками 1, 3, 7, 14 дней; свой стиль, без названий и материалов оригинальных игр. Интерфейс крупный, кнопки от 48 px, работает пальцем, пером и мышью на планшете и ноутбуке.

## Как вести большую работу над игрой

Образец — `apps/oborona-tablicy/dev/`: `00-plan.md` (этапы и кто делает), `01-arhitektura.md` (модули, модель данных, правила, отладочный интерфейс `window.OT`, список приёмочных тестов, принятые решения), затем по файлу на этап с тремя разделами «Что сделано», «Что осталось», «Находки и решения», и финальное ревью с таблицей требований. Решения оркестратора дописываются в конец соответствующего файла. Скриншоты в `dev/shots/`.

## Проверка перед коммитом

- `python3 tools/build_site.py` проходит без ошибок (он проверяет манифесты и иконки).
- Для игр с тестами: `node tools/test_app.mjs <имя>` зелёный; перед тестами «Сайт» нужна свежая сборка.
- `git status` не показывает `docs/`.
- Коммиты и PR на русском с описанием, что изменилось для ребёнка и родителя.
