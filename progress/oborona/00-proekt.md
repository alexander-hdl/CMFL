## 1. Игра в двух словах и поток экранов

Враги идут по дорожкам к крепости, на щите у каждого число. Ребёнок ставит башни-цифры на площадки и натягивает лучи между соседними башнями. Над лучом всегда написано «a × b = c». Враг исчезает, пройдя луч с таким же произведением. Подготовка перед волной без таймера, пауза всегда доступна.

Экраны (одновременно виден один):

| id экрана | Что на нём | Откуда | Куда |
|---|---|---|---|
| `map` | Карта мира: 6 земель, уровни, звёзды, награды, кнопка «Для взрослых» | старт, «На карту» | `level`, `adult` |
| `level` | Поле боя (canvas) + верхняя полоса + рука | кнопка уровня на карте, «Ещё один уровень» | `levelEnd` |
| `levelEnd` | «Уровень пройден!», звёзды, сердечки, «можно было ещё» | конец 3-й волны | `map` или `night` |
| `night` | «Крепость закрывается на ночь»: освоено, вернутся завтра, приём | после 3-го уровня сессии или при лимите дня | `level` («Ещё один уровень») или `map` |
| `adult` | Экран взрослого | удержание кнопки 2 с на карте | `map` |

Этап 1 (прототип) открывает сразу `level` с демонстрационной волной; экранов `map`, `night`, `adult` в нём нет.

Фазы внутри `level`: `prep` (подготовка) → `battle` (волна идёт; флаг `paused`) → `waveEnd` (1500 мс, тост) → снова `prep` следующей волны или `levelEnd` после 3-й волны.

## 2. Архитектура одного HTML-файла

### 2.1. Формат файла `plan/oborona.html`

Строго как в конвенциях: `<title>Оборона таблицы</title>`, затем `<link>` на Google Fonts (как в арене: `family=Nunito:wght@500;700;800&family=Russo+One&display=swap`, плюс два `preconnect`), один `<style>`, разметка без `<html>/<head>/<body>`, один `<script>`. Внутри скрипта — одна IIFE `(function () { "use strict"; … })();`, разделённая комментариями-заголовками модулей в порядке ниже. Внешних картинок, звуков, библиотек нет.

### 2.3. Как сосуществуют canvas и DOM

- `#field` — `position: fixed; inset: 0`, рисует траву, дорожки, площадки, башни, лучи, подписи лучей, врагов, всплывающие тексты, выделение, подсказку-путь. Всё в единицах поля через `ctx.setTransform` (раздел 3.2).
- `#bar` (сверху) и `#hand` (снизу) — DOM поверх canvas, `position: fixed`, непрозрачный фон `--panel`. Поле вписывается между ними, они его не перекрывают.
- `#pauseOv` — плашка под `#bar` по центру (ширина до 520 px); поле под ней остаётся доступным для касаний.
- Экраны `.screen` — `position: fixed; inset: 0`, непрозрачные, поверх всего; пока открыт экран, цикл рисования поля не работает (симуляция и так стоит).
- Все обработчики касаний — Pointer Events. На `#field`, `#hand`, `#ghost`: `touch-action: none; user-select: none; -webkit-user-select: none; -webkit-touch-callout: none`; `contextmenu` отменяется (долгое касание пером не открывает меню).
- Перетаскивание плитки начинается в DOM (`#tiles`), продолжается призраком `#ghost` (`position: fixed`, следует за указателем, `pointer-events: none`), заканчивается переводом координат указателя в единицы поля (`toField`, раздел 3.2) и поиском площадки.

### 2.5. Цикл и фиксированный шаг

- Симуляция идёт только тиками по `DT = 1000/60` мс. Скорость рисования на неё не влияет.
- `LOOP`: на каждом кадре `acc += min(250, now − last)`; пока `acc ≥ DT` и фаза `battle` без паузы (или `waveEnd`) — `tick()`, `acc −= DT`. Затем `render()`.
- Ручной режим для тестов: `api.manual(true)` — `LOOP` перестаёт вызывать `tick()` (рисует дальше), время двигают только `api.step(ms)` = `Math.round(ms / DT)` тиков подряд.
- `document.visibilitychange` со скрытием страницы во время `battle` ставит паузу.

## 3. Геометрия

### 3.1. Константы (в единицах поля)

| Имя | Значение | Смысл |
|---|---|---|
| `FIELD_W × FIELD_H` | 1600 × 900 | всё поле |
| `PATH_HALF` | 40 | полуширина дорожки (рисуется 80 ед. + кайма 8 ед.) |
| `PAD_R` | 44 | радиус площадки |
| `PAD_OFFSET` | 165 | расстояние центра площадки от оси дорожки (в раскладках выдержано ≥ 165) |
| `TOWER_R` | 40 | радиус основания башни (рисуется внутри площадки) |
| `ENEMY_R` / `BOSS_R` | 34 / 48 | радиус тела врага / босса |
| `LABEL_BAND` | 85 | расстояние центра подписи луча от оси дорожки |
| `LABEL_FONT` | 40 | кегль подписи луча; фактический `max(40, 22 / s)`, при «Крупном шрифте» `max(50, 26 / s)` |
| `PLATE_PAD_X`, `PLATE_H` | 14, кегль + 16 | поля плашки подписи |
| `ENEMY_FONT` / `BOSS_FONT` | 40 / 46 | число на щите |
| `TOWER_FONT` | 44 | цифра на башне |
| `FORT_R` | 70 | радиус крепости |

### 3.2. Масштаб под экран

- Высота полос: если `innerHeight < 700`, то `BAR_H = 68`, `HAND_H = 84`; иначе `BAR_H = 76`, `HAND_H = 92` (px).
- `availW = innerWidth`, `availH = innerHeight − BAR_H − HAND_H`.
- `s = min(availW / 1600, availH / 900)` — px на единицу, пропорции сохраняются.
- `ox = (availW − 1600·s) / 2`, `oy = BAR_H + (availH − 900·s) / 2` — левый верхний угол поля в px. Поля вокруг заливаются цветом травы `--grass-2`.
- Canvas: CSS-размер = окно, буфер = окно × `dpr`, `dpr = min(2, devicePixelRatio)`. Перед рисованием поля: `ctx.setTransform(dpr·s, 0, 0, dpr·s, dpr·ox, dpr·oy)`.
- Перевод указателя: `toField(cx, cy) = { x: (cx − ox) / s, y: (cy − oy) / s }` (`cx, cy` — `clientX/clientY`, canvas на весь экран).
- Проверка: 1024×600 → `s ≈ 0,498`; 1024×768 → `s = 0,64`; 1366×768 → `s ≈ 0,684`; 1920×1080 → `s = 1,0`.
- На `resize` и `orientationchange` пересчитать и перестроить кэш фона; после `document.fonts.ready` — тоже.

### 3.3. Дорожки как ломаные и параметр t

- Дорожка — массив точек `[[x0,y0],[x1,y1],…]`. Враг появляется в первой точке и идёт к последней (у крепости).
- При подготовке раскладки (`prepareLayout`) для каждой дорожки считаются длины отрезков `seg[i]`, накопленные длины `cum[0]=0, cum[i]=cum[i−1]+seg[i−1]` и общая длина `len`.
- Положение врага — `t ∈ [0, 1]` (доля пройденной длины). Точка по `t`: найти отрезок `i`, где `cum[i] ≤ t·len ≤ cum[i+1]`, и интерполировать.
- Шаг: `t += speed · DT / 1000 / len`, где `speed` в ед./с (раздел 5.7). `t ≥ 1` — враг у крепости.

### 3.4. Площадки, связи и лучи

- Площадка — `{id: "A", x, y}`. Связь (`link`) — пара площадок, между которыми разрешён луч, задаётся в раскладке явно: `{a: "A", b: "B", labelToward: "A"}`. «Соседняя башня» = башня на площадке, связанной с выбранной.
- Луч — отрезок между центрами двух башен. В раскладках гарантировано: отрезок каждой связи пересекает каждую дорожку не более одного раза и хотя бы одну дорожку ровно один раз.
- `prepareLayout` для каждой связи и каждой дорожки перебирает отрезки ломаной и вызывает `segmentIntersection(A, B, P_i, P_{i+1})`. При пересечении: `tCross = (cum[i] + v · seg[i]) / len`, где `v` — параметр на отрезке дорожки. Результат: `link.cross = [{path, t, x, y}, …]`.
- Подпись луча стоит на самом луче, со стороны площадки `labelToward`, в точке луча на расстоянии `LABEL_BAND = 85` от оси дорожки (ищется делением отрезка пополам между точкой пересечения и центром этой площадки; в раскладках ниже уже посчитана — поле `labelAt`). Чередование сторон подобрано так, что плашки 320 × 66 ед. не перекрывают друг друга, дорожку, площадки и крепость.

### 3.5. Когда враг «проходит через луч»

- На каждом тике у врага есть `tPrev` и `tNew`. Луч действует на врага, если среди `link.cross` есть элемент с `path === enemy.path` и `tPrev < t ≤ tNew`.
- Если за тик пересечено несколько лучей — обработать по возрастанию `t`.
- Луч, построенный на паузе позади врага (`t ≤ enemy.t`), на этого врага уже не действует. Каждый луч действует на врага не больше одного раза (это следует из возрастания `t`).
- Луч, у которого убрали башню, исчезает сразу; враг, который «был под ним», ничего не получает.

### 3.6. Попадание касанием

- Площадка ловит башню при отпускании, если расстояние от указателя до центра площадки в px ≤ `PAD_R·s + 40` (то есть «радиус 40 px» считается от края площадки). При нескольких — ближайшая.
- Касание башни: расстояние ≤ `PAD_R·s + 16` px.
- Касание луча: внутри плашки подписи (с запасом 8 px) **или** расстояние до отрезка луча ≤ 20 px. Если подходят два луча — тот, чья плашка ближе.
- Порог «касание или перетаскивание» — сдвиг 12 px.

## 5. Правила боя

### 5.1. Башни и лучи

- Башня — цифра из руки на площадке. На площадке одна башня. Цифры в руке бесконечны.
- Луч — между двумя башнями на связанных площадках. На одной связи один луч. Одна башня — не больше двух лучей.
- Произведение луча = произведение цифр башен. Подпись: «a × b = c», где `a` — башня, нажатая первой, `b` — второй (`beam.from`, `beam.to`). При смене цифры на башне луч остаётся, произведение и подпись пересчитываются.
- Подпись видна всегда, в любой фазе, на паузе и во время вспышки луча. Исключений нет (это приёмка).

### 5.2. Обычный враг

- `product === value` → враг побеждён: «хлопок» 400 мс (кружки-искры), луч мягко светлеет 300 мс.
- `product !== value` → враг проходит без урона; луч один раз плавно сереет и возвращается за 600 мс (не мерцает); над врагом 1000 мс текст **`«{value}, а луч даёт {product}»`**, например «56, а луч даёт 42».

### 5.3. Бронированный босс

Пусть `v` — текущее число босса, `p` — произведение луча.
- `p === v` → босс побеждён.
- `p < v` и остаток `r = v − p` можно добить (`canFinish(r, hand)`, раздел 14) → число босса становится `r`; текст 1500 мс **`«{v} − {p} = {r}»`**, например «56 − 35 = 21»; на броне появляется трещина; луч светится оранжевым 400 мс.
- `p < v`, но остаток добить нельзя (при руке 2–9 это остатки 1, 2, 3, 5, 7, 11) → проходит без урона, текст **`«Останется {r} — такого луча нет»`** **[решение]**.
- `p > v` → проходит без урона, текст **`«{v}, а луч даёт {p}»`**, например «21, а луч даёт 35» или «56, а луч даёт 63».
- Пример: босс 56, лучи 7 × 5 и 7 × 3 → «56 − 35 = 21», число 21, затем побеждён. Порядок лучей не важен: 56 − 21 = 35, затем луч 35.
- Босс идёт со скоростью 0,8 от обычной, больше размером, щит шире (раздел 18).

### 5.4. Земля деления

- Неподвижные башни (`fixed: {B: 7, …}`) стоят с начала уровня, их нельзя убрать, переставить, сменить цифру (`reason: "fixed"`). Лучи от них строятся обычным образом.
- Пример приёмки: стоит башня 7, идёт враг 56 — из всех напарников 2–9 побеждает только 8.

### 5.5. Двузначные боссы (земля 6)

- В руке добавляются плитки 10, 20, 30, 40 **[решение: 40 добавлено, без него 47 × 2 не разрезать по разрядам]**.
- Босс 92 (карточка `4x23`): луч 4 × 20 = 80 → «92 − 80 = 12», луч 4 × 3 = 12 → побеждён. Подписи «20 × 4 = 80» или «4 × 20 = 80» — в порядке нажатия.

### 5.6. Сердечки, крепость, звёзды

- На уровень 10 сердечек на все 3 волны. Враг (или босс), дошедший до крепости (`t ≥ 1`), снимает одно; меньше 0 не бывает.
- Без позора: враг останавливается у ворот, «стучит» 600 мс и растворяется облачком; у крепости 2000 мс спокойный текст с правильным разложением **`«56 = 7 × 8»`** (первая пара из `pairsFor`; для босса — исходная карточка, например «92 = 4 × 23»; если пар нет — просто число). Сердечко в полосе плавно тускнеет и число уменьшается. Никаких красных вспышек, тряски, слов «проиграл».
- Уровень всегда доигрывается до конца 3-й волны, даже при 0 сердечек.
- Звёзды: `starsFor(hearts)`: 8–10 → 3, 4–7 → 2, 0–3 → 1. В сохранении лучший результат уровня.

### 5.7. Скорость и время

- Скорость врага по умолчанию 50 ед./с **[решение]**; настройка взрослого: «Медленно» 35, «Обычно» 50, «Быстрее» 65. Умножается на `layout.speedMul` и на 0,8 для босса.
- Интервал появления врагов 3000 мс (облегчённая волна 4500 мс); перед боссом дополнительно +1500 мс.
- Оценка: L1 при 50 ед./с — 30 с на проход, волна из 8 врагов ≈ 51 с; 3 волны с подготовкой ≈ 4–6 минут.

## 6. Управление

Все цели касания от 48 px; плитки руки 64–76 px; «В бой!», «Пауза», «Дальше» — 64 px высотой.

### 6.1. Рука

- Плитки: земли 1 — 2…9 и 10; земли 2–5 — 2…9; земля 6 — 2…9, 10, 20, 30, 40. Размер плитки `min(76, (W − 200 − 6·(n − 1)) / n)` px, не меньше 56. У плитки цветная полоса цвета цифры (раздел 18) и крупная цифра шрифтом Russo One.
- Перетаскивание: `pointerdown` на плитке → `setPointerCapture`, появляется `#ghost` (копия плитки 1,1×) под указателем; `pointermove` двигает его и подсвечивает площадку, которая поймает (кольцо `--gold`); `pointerup` → `api.placeTower(pad, value)` для пойманной площадки или ничего.
- Касание без перетаскивания: плитка выбирается (золотая рамка), следующее касание площадки ставит туда башню; повторное касание плитки снимает выбор. Это для пера и мыши.
- Отпускание на занятой (не неподвижной) площадке меняет цифру башни.
- Игнорировать неосновные указатели (`isPrimary === false`) во время перетаскивания.

### 6.2. Башни и лучи на поле

- Касание башни → башня выбрана (золотое кольцо), связанные с ней площадки с башнями подсвечены пунктирным кольцом. Касание подсвеченной башни → `api.beam(первая, вторая)`, выбор снимается. Касание выбранной башни — снять выбор. Касание другой несвязанной башни — выбор переходит на неё.
- Отказы показываются коротким текстом у башни на 1000 мс (без звука ошибки): `"full"` → «У башни уже два луча»; `"no-tower"` → «Сначала поставь башню»; `"exists"` — луч уже есть, просто снять выбор.
- Касание плашки подписи (или самого луча) → луч выбран: плашка в золотой рамке, справа от неё круглая кнопка «✕» диаметром `max(56 ед., 48 px)`. Касание «✕» → `api.breakBeam(id)`. Касание мимо — снять выбор. Так различаются два луча одной башни: у каждого своя плашка.
- Перетаскивание башни (сдвиг > 12 px) → перестановка: на пустую площадку — переезд, на занятую — обмен цифрами; лучи обеих башен рвутся. Отпускание вне площадок или над рукой — башня убирается, её лучи рвутся. Неподвижные башни не тянутся.
- Когда можно менять: в `prep` и при `paused`. В `battle` без паузы касания поля игнорируются, плитки руки затемнены (`opacity: .45`), кнопка «В бой!» скрыта; при касании поля один раз за уровень мягкий тост «Нажми „Пауза“, чтобы перестроить лучи».

### 6.3. Кнопки

- «В бой!» — справа в руке, видна только в `prep`, всегда доступна (можно идти без лучей).
- «Пауза» — справа в полосе, видна в `battle`. На паузе — плашка `#pauseOv`: «Пауза», «Лучи можно перестроить», «Дальше», «На карту» (уровень не засчитывается). Пробел и `Escape` тоже ставят/снимают паузу.

## 9. Подстройка под ребёнка

### 9.1. Карточки и коробки Лейтнера

- Карточка `facts[key]` создаётся при первом появлении факта в волне с `box: 1, due: today`. Коробка 0 = «ещё не встречался» (карточки нет).
- Интервалы `INTERVALS = {1: 0, 2: 1, 3: 3, 4: 7, 5: 14}` дней (как в арене).
- Карточка «пора повторить» (`due`), если `box ≥ 1` и `due ≤ today`.
- Повышение — не чаще раза в день: только если карточка была `due` на момент обновления. Так 7x8, побеждённый пять раз за вечер, уходит из коробки 1 в коробку 2, а в коробку 3 — только на следующий день.

`leitnerUpdate(card, outcome, today)`:

| outcome | Условие | Результат |
|---|---|---|
| `"good"` | `card.due ≤ today` | `box = min(5, box + 1)`, `due = addDays(today, INTERVALS[box])` |
| `"good"` | `card.due > today` | коробка и `due` не меняются |
| `"fail"` | всегда | `box = 1`, `due = today` |
| `"ok"`, `"none"` | всегда | не меняются |

Во всех случаях `lastDay = today`; если `box` стал ≥ 3 впервые — `masteredOn = today`.

### 9.2. Исход врага и исход карточки за волну

Для каждого луча в бою известны: `phase` (`"prep"` — луч существовал в момент «В бой!»; `"battle"` — создан или изменён на паузе) и `linkEdits[linkId]` — сколько раз в этой волне на этой связи луч создавался или менял произведение. В начале подготовки каждой волны `linkEdits[link] = (луч есть) ? 1 : 0`; создание луча и смена цифры его башни — `+1`. При «В бой!» всем существующим лучам ставится `phase = "prep"`.

Исход врага (в момент, когда он исчез):
- дошёл до крепости → `fail` для `enemy.card`;
- побеждён лучом `L`, у которого `phase === "prep"` и `linkEdits[L] ≤ 2` («перестраивали не больше одного раза») → `good`;
- побеждён иначе → `ok`.
- Для босса условие `good` проверяется у всех лучей, которые его уменьшали или победили.

Какой карточке засчитывается:
- обычный враг побеждён → карточке луча `factKey(beam.from.value, beam.to.value)`; если она отличается от `enemy.card` (24 побеждён лучом 4 × 6, а волна выбрала 3 × 8), задуманная карточка получает `none`;
- босс → всегда `enemy.card`; плюс `bossDays` (если `good`/`ok`);
- уровень земли 5, враг побеждён лучом с неподвижной башней → карточке луча плюс `divDays`;
- дошёл → `fail` для `enemy.card`.

`waveOutcome(enemyResults)` → `{ "7x8": "good", … }`: для каждой карточки: есть `fail` → `fail`; иначе есть `good` → `good`; иначе `ok`. После этого `leitnerUpdate` по каждой карточке один раз. Статистика: `seen += 1` для каждой карточки волны, `good/ok/fail += 1` по итогу.

### 9.3. Путаницы

Когда враг `v` проходит луч `p ≠ v` и одновременно (а) на дорожке врага нет луча с произведением `v`, (б) `p` не равно числу ни одного врага этой волны, — записать путаницу `confusions[confusionKey(v, p)] += 1` (не чаще раза на пару за волну). Пример: врагу 56 построен только луч 6 × 8 = 48 → пара `"48|56"`. Показ взрослому — «56 ↔ 48» (больше слева).

### 9.4. Время построения луча (для взрослого)

При создании луча в `prep`, если его произведение равно числу какого-то врага волны: `ms = now − max(prepStart, lastBeamAt)`, не больше 120000; добавить в `msSum/msN` карточки луча. `lastBeamAt = now`. Ребёнку не показывается нигде.

### 9.5. Сборка волны `buildWave(profile, ctx, seed)`

Вход:
- `profile` — `{facts, confusions, heavyStreak, lightStreak}` из сохранения;
- `ctx` — `{land, levelId, waveIndex, layout (подготовленная), hand, fixed, wave: {n, k, b}, unlocked: [1,2,…], today}`;
- `seed` — 32-битное целое. В игре `seed = hashSeed(levelId + "|" + waveIndex + "|" + today + "|" + plays)` (FNV-1a); тесты передают своё.

ГСЧ — `mulberry32(seed)` (стандартный: `a += 0x6D2B79F5; t = Math.imul(a ^ a >>> 15, a | 1); t ^= t + Math.imul(t ^ t >>> 7, t | 61); return ((t ^ t >>> 14) >>> 0) / 4294967296`). Больше `Math.random` в логике нигде нет.

Шаги (строго по порядку):

1. **Режим.** `easy = profile.heavyStreak ≥ 2`. Если `easy`: `n = 6`, `k = max(1, k − 1)`, новых нет, интервал 4500 мс. Если `profile.lightStreak ≥ 2` и не `easy`: `k = min(4, k + 1)`.
2. **Пулы карточек** (только факты из земель `≤ ctx.land`, которые открыты; для земли 5 — только карточки, где есть хотя бы одна цифра из `ctx.fixed`; для земли 6 обычные враги — из земель 1–4):
   - `NEW` — карточки текущей земли без записи в `facts`, в порядке списка земли;
   - `DUE` — `dueCards(facts, today)`, сначала текущей земли, затем остальные; внутри — по `due`, затем по `box` по возрастанию;
   - `FAM` — `box ≥ 1`, не `due`; сначала текущей земли; сортировка по `box` по возрастанию, при равенстве — порядок ГСЧ.
3. **Боссы** (если `b > 0`): карточка босса — первая из (`DUE` ∩ боссы земли) → (боссы с наименьшим `box`) → (`NEW` ∩ боссы); боссы земли 4 — «Трудные пятнадцать», земли 6 — двузначные. `split = splitHint(a, b)`. Для 3x3 разрезания нет — босс 9 бьётся только лучом 3 × 3. Карточки частей (`factKey` из `split.beamParts`, для 7x8 это `5x7` и `3x7`) становятся «свитой» и занимают места в `k` (если части одинаковые, как 9 + 9, — одно место).
4. **Число разных карточек** `k` распределяется: новых `kNew = (easy || NEW пуст) ? 0 : 1`; повторяемых `kDue = min(|DUE|, k ≥ 4 ? 2 : 1)`; остальные — знакомые. Нехватку в категории добирать по цепочке `DUE → FAM → NEW` (в самом начале игры все `k` карточек — новые). Если всех карточек меньше `k`, `k` уменьшается.
5. **Путаницы.** Если у выбранной карточки число `v` есть путаница с `n ≥ 2`, а у числа-пары `p` есть карточка в пулах, заменить последнюю знакомую карточку карточкой `pairsFor(p, hand)[0]`. Не больше одной пары на волну.
6. **Врагов на карточку** (`n` всего, боссы — `b` из них): `nNew = round(0,1·n)` (мин. 1, если есть новая), `nDue = round(0,2·n)` (мин. 1 на каждую повторяемую), остальное — знакомым поровну, остаток первым. Пустая категория отдаёт своих врагов знакомым. Свита босса считается знакомыми. Пример `n = 10`: 1 новый, 2 повторяемых, 7 знакомых; `n = 8`: 1 / 2 / 5; `n = 6`: 1 / 1 / 4.
7. **Решаемость.** `solveWave(layout, demands, {hand, fixed})` (раздел 14). `demands` — разные пары `(value, kind)` волны. Если решения нет: заменить последнюю знакомую карточку следующей кандидатурой (до 30 попыток), затем уменьшить `k` на 1 и повторить. С `k = 1` решение есть всегда (раскладки это гарантируют).
8. **Порядок появления.** Перемешать список врагов (Фишер — Йетс на ГСЧ). Первого босса поставить на позицию `floor(0,6·n)`, второго — последним. Дорожка каждого врага — та, что выбрал решатель для его числа. `spawnAt[i] = i · gap` (+1500 мс перед каждым боссом).

Выход:
```
{
  enemies: [ {value: 56, kind: "boss", card: "7x8", path: 0, spawnAt: 15000}, {value: 35, kind: "normal", card: "5x7", path: 0, spawnAt: 0}, … ],
  cards: ["7x8", "5x7", "3x7"],
  solution: { pads: {A: 5, B: 7, C: 3}, beams: [["A","B"], ["B","C"]], paths: {"56b": 0, "35": 0, "21": 0} },
  meta: { easy: false, newCount: 0, dueCount: 1, famCount: 2, n: 8, k: 3, gap: 3000, seed: 12345 }
}
```
Гарантия: если поставить башни `solution.pads` и построить лучи `solution.beams`, все враги волны побеждены (проверяется тестом через настоящую симуляцию).

### 9.6. Около 80 % побед и облегчение

После каждой волны:
- `share = побеждено / всего`, `lost` — снятые сердечки в этой волне.
- Волна «тяжёлая», если `share < 0,7` или `lost ≥ 3` → `heavyStreak += 1`, иначе `heavyStreak = 0`.
- Волна «лёгкая», если `share === 1` и все победы `good` → `lightStreak += 1`, иначе `lightStreak = 0`.
- После облегчённой волны `heavyStreak = 0`.

Так две тяжёлые волны подряд дают облегчённую (6 врагов, на одно число меньше, без новых, реже), а две идеальные подряд — на одно число больше.

## 10. Сессия, итоги, подсказки

### 10.1. Сессия и лимит дня

- `save.today = {date, levels, session}`. При запуске и перед каждым уровнем: если `date !== today()`, обнулить `levels` и `session`.
- Уровень засчитывается, когда закончилась 3-я волна: `levels += 1`, `session += 1`. Ушёл на карту с паузы или перезагрузил страницу посреди уровня — не засчитывается, прогресс уровня не сохраняется **[решение]**.
- После `levelEnd` кнопка «Дальше»: если `session ≥ 3` или `levels ≥ settings.perDay` → экран `night`, иначе → `map`.
- На `night`: если `levels < perDay` — кнопка «Ещё один уровень» (следующий открытый уровень после последнего сыгранного, иначе тот же); иначе крупная надпись **«Крепость отдыхает до завтра»** и кнопка «На карту». После показа `night` — `session = 0`.
- На карте при `levels ≥ perDay`: та же надпись сверху, кнопки уровней неактивны; `api.startLevel` возвращает `{ok: false, reason: "limit"}`.
- `today()` = `window.OBORONA_TODAY` (если задан — для тестов) или локальная дата `YYYY-MM-DD`.

### 10.2. Экран конца уровня `levelEnd`

- «Уровень пройден!», три звезды (заполненные по `starsFor`), «Сохранено 8 сердечек из 10» (через `plural`).
- До 2 строк «можно было ещё»: для каждого числа, побеждённого на уровне, у которого `pairsFor(v, hand)` даёт ≥ 2 пары, — пара, которой он **не** пользовался: **«24 можно было победить ещё лучом 4 × 6»** (пара пишется `a × b`, `a ≤ b`).
- Кнопка «Дальше».

### 10.3. Экран «Крепость закрывается на ночь» (`night`)

- Заголовок «Крепость закрывается на ночь».
- «Освоено сегодня:» — карточки с `masteredOn === today`, через запятую как «7 × 8». Если нет: «Пример становится освоенным, когда побеждаешь его в два разных дня».
- «Завтра вернутся:» — карточки, встреченные сегодня (`lastDay === today`) с `due ≤ завтра`, до 8 штук.
- «Можно было ещё:» — до 3 строк как в 10.2 за весь день.
- «Приём:» — одна подсказка `tipFor` (10.5) для самой трудной сегодняшней карточки (наименьший `box`, при равенстве — больше `fail`).
- Кнопки: «Ещё один уровень» или надпись «Крепость отдыхает до завтра»; «На карту».

### 10.4. Подсказка-путь для разрезания боссов

- Что рисуется: пунктир (штрих 18, пробел 12, толщина 6 ед., белый 70 %) по оси дорожки от входа до точки пересечения связи, где по `solution` стоит первая часть (`beamParts[0]`, для 7x8 это 7 × 5); пунктирные кольца на двух площадках этой связи и призрачная плашка «7 × 5» в `labelAt`.
- Когда видна (на карточку босса `facts[key]`):
  - пока `noHintDays.length < 2` подсказка существует; при `noHintDays.length ≥ 2` — не показывается никогда;
  - первые две встречи (`bossSeen < 2`) — видна сама в подготовке и в бою;
  - дальше скрыта, но на карточке босса в ленте есть кнопка-лампочка; касание показывает подсказку до конца волны.
- Босс побеждён в волне, где подсказка была скрыта и лампочку не нажимали, → добавить `today` в `noHintDays` (без повторов). Так выполняется «видна, пока босс не побеждён без неё в два разных дня».

### 10.5. Подсказки-приёмы `tipFor(a, b, {boss})`

Шаблоны подставляют сам пример (`x` — второй множитель):

| Ряд | Текст |
|---|---|
| ×9 | «×9 — это ×10 и минус одно: 7 × 9 = 7 × 10 − 7 = 70 − 7 = 63» |
| ×6 | «×6 — это ×5 и плюс одно: 6 × 7 = 5 × 7 + 7 = 35 + 7 = 42» |
| ×4 | «×4 — это удвоить дважды: 4 × 7: 7 → 14 → 28» |
| ×8 | «×8 — это удвоить трижды: 8 × 7: 7 → 14 → 28 → 56» |

## 12. Экран взрослого (`adult`)

- Вход: на карте, внизу слева, небольшая кнопка «Для взрослых» (48 px). Нужно удерживать 2000 мс: вокруг кнопки заполняется кольцо; отпускание раньше — сброс. На поле боя кнопки нет.

### 13.1. Где

### 14.1. Правила `splitHint(a, b)`

- Оба однозначные: держим меньший множитель `x`, режем больший `y`. `y ≥ 7` и не 9 → `5 + (y − 5)`; `y = 9` → текст «x × 9 = x × 10 − x» (`op: "−"`), но `beamParts` = `[[x,5],[x,4]]` (лучами вычитать нельзя, только отнимать у босса); `y` чётное (4, 6) → половины (`3 × 6 = 3 × 3 + 3 × 3`, `4 × 6 = 4 × 3 + 4 × 3`, `6 × 6 = 6 × 3 + 6 × 3`, `4 × 4 = 4 × 2 + 4 × 2`, `3 × 4 = 3 × 2 + 3 × 2`); `y = 5` → `2 + 3`; `y = 3` (только 3 × 3) → `null`.
- Таблица для «Трудных пятнадцати»: 3x4 → 3×2+3×2; 3x6 → 3×3+3×3; 3x7 → 3×5+3×2; 3x8 → 3×5+3×3; 4x4 → 4×2+4×2; 4x6 → 4×3+4×3; 4x7 → 4×5+4×2; 4x8 → 4×5+4×3; 6x6 → 6×3+6×3; 6x7 → 6×5+6×2; 6x8 → 6×5+6×3; 7x7 → 7×5+7×2; 7x8 → 7×5+7×3; 8x8 → 8×5+8×3; 3x3 → нет.
- Двузначное × однозначное: режем по разрядам: 12×3 → 10×3+2×3; 14×4 → 10×4+4×4; 23×4 → 20×4+3×4; 25×3 → 20×3+5×3; 35×2 → 30×2+5×2; 47×2 → 40×2+7×2; 16×5 → 10×5+6×5; 19×4 → 10×4+9×4. Текст пишется в порядке «двузначное × однозначное»: «23 × 4 = 20 × 4 + 3 × 4».

### 14.2. Решатель `solveWave`

- `demands`: `[{value, kind: "normal"|"boss", parts?}]`, у босса `parts = splitHint(...).beamParts` или `null` (3x3).
- Состояние: `pads` (начинается с `fixed`), `beams` (связь → `{from, to}`), счётчик лучей у площадки (≤ 2).
- Порядок: сначала боссы, затем обычные по числу пар `pairsFor` по возрастанию.
- Обычный: (1) если уже есть луч с произведением `value` на какой-то дорожке — взять его; (2) иначе перебор: дорожки по номеру → связи в порядке раскладки, пересекающие дорожку и свободные → пары `pairsFor(value, hand)` → две ориентации (`x` на `a`, `y` на `b`; потом наоборот; при `x = y` одна). Площадка подходит, если пуста или уже несёт ту же цифру, и у неё меньше 2 лучей. Неподвижную цифру менять нельзя.
- Босс с `parts`: дорожка → упорядоченная пара разных свободных связей на ней → каждая часть на свою связь в двух ориентациях. Босс без `parts` — как обычный.
- Когда все требования размещены — проверка: для каждого требования взять лучи на его дорожке по возрастанию `t` и прогнать `hitResult`; все должны закончиться `kill`. Не прошло — откат и дальше.
- Выход `{pads, beams: [[from,to],…], paths: {"35": 0, "56b": 0}}` (ключ обычного — число, босса — число + `b`) или `null`, если перебор кончился или превысил `maxNodes = 20000`.

### 18.2. Как рисовать

- **Фон** (кэш-холст): полосы травы; 10–14 «кустов» (по 3 круга `#6aae52`) и «камней» (эллипсы `#b9b2a3`) в фиксированных точках раскладки, не ближе 90 ед. к дорожке и площадкам; дорожка — ломаная `lineJoin/lineCap = "round"`: сначала кайма 88 ед., затем 80 ед.; вход — тёмная арка (полукруг `#3d3550` радиусом 60 у первой точки).
- **Крепость**: прямоугольник стены 150 × 120 ед. `--stone` с зубцами (5 прямоугольников 20 × 18 сверху), две башенки по бокам (круги 34 ед.) с конусами-крышами `--roof`, ворота — скруглённая арка `--wood`. Награды добавляют пушки (чёрные круги + стволы), весы, вторую башню.
- **Площадка**: круг `PAD_R` `--pad` с кольцом 6 ед. `--pad-ring`. Свободная площадка, которую поймает перетаскивание, — золотое кольцо 8 ед.
- **Башня**: основание — круг 40 ед. `--wood` с тремя тёмными «досками» (дуги); верх — круг 30 ед. цвета цифры (или фигура вида из раздела 11: шестиугольник, звезда, восьмиугольник, ромб, полосатый маяк с жёлтым кругом-лампой); цифра белая 44 ед. с обводкой 6 ед. `--ink-dark`. Неподвижная башня — основание `--stone` с четырьмя кружками-заклёпками. Выбранная — кольцо `--gold` 6 ед. радиусом 54.
- **Луч**: две линии между центрами башен — широкая 22 ед. `--beam` с прозрачностью 0,35 и узкая 8 ед. `--beam-core`. Серый «мимо»: цвет плавно уходит в `--beam-grey` и возвращается за 600 мс. «Отнял»: `--beam-hit` 400 мс. «Победил»: широкая линия 30 ед. 300 мс. Никаких миганий чаще одного раза.
- **Плашка подписи**: скруглённый прямоугольник (радиус 14) `#fffbe6`, обводка 4 ед. `--ink-dark`, текст `--ink-dark` по центру; выбранная — обводка `--gold` 6 ед. и кнопка «✕» (круг `--bad`, белый крест).
- **Враг**: тело-капля (круг `ENEMY_R` `--enemy` + два маленьких круга-ножки, которые чередуются по высоте на 3 ед. с периодом 400 мс), белые глаза с тёмными зрачками, смотрят по ходу дорожки; перед телом — щит: скруглённый прямоугольник 80 × 50 ед. `--shield` с обводкой, число 40 ед. `--ink-dark`. Обычные враги не носят брони.
- **Босс**: тело `BOSS_R` `--boss`, кольцо брони 10 ед. `--armor`, два рога-треугольника, щит 104 × 60 ед., число 46 ед.; после каждого «отнял» — тёмная ломаная трещина на броне.
- **Победа**: 8 кружков-искр цвета `--beam` разлетаются на 40 ед. за 400 мс и тают. **Дошёл**: враг идёт в ворота, уменьшается до 0 за 600 мс, у ворот всплывает «56 = 7 × 8».
- **Всплывающий текст**: плашка как у подписи, кегль 36 ед., поднимается на 30 ед. за время жизни, последние 200 мс тает.
- `prefers-reduced-motion: reduce`: без искр, без ножек, без подъёма текста, вспышки лучей заменяются сменой цвета без перехода; в CSS — как в конвенциях.

## 20. Риски, открытые вопросы и решения по умолчанию

| № | Вопрос / риск | Решение по умолчанию |
|---|---|---|
| 1 | Как различать касанием два луча одной башни | У каждого луча своя плашка подписи, они не перекрываются (проверено `validateLayout`). Касание плашки выбирает луч, «✕» рвёт. Касание самой башни всегда выбирает башню. |
| 2 | Что с лучом, если башню убрали или переставили | Все лучи этой башни рвутся сразу. При смене цифры лучи остаются, произведение пересчитывается (`edits + 1`). |
| 3 | Как показать «враг прошёл в крепость» без позора | Враг тихо уходит в ворота, сердечко плавно тускнеет, у ворот спокойная подсказка «56 = 7 × 8». Ни красного, ни тряски, ни слов про проигрыш; уровень доигрывается. |
| 4 | Скорость по умолчанию | 50 ед./с (≈ 30 с на проход L1), на L3 ×1,25, босс ×0,8; взрослый выбирает 35 / 50 / 65. |
| 5 | Остаток босса, который нельзя добить (1, 2, 3, 5, 7, 11) | Луч не действует, текст «Останется 2 — такого луча нет». Альтернатива «уменьшать всегда» отвергнута: босс стал бы непобедимым. |
| 6 | В ТЗ в руке 10, 20, 30, а 47 × 2 по разрядам требует 40 | Добавлена плитка 40 на земле 6. |
| 7 | «Видна, пока не побеждён без неё в два разных дня» — как победить без неё, если она видна | Первые 2 встречи — видна сама, дальше спрятана под лампочкой; победа без лампочки — день в `noHintDays`; два дня — подсказка исчезает. |
| 8 | Порядок множителей в подписи | Как нажимал ребёнок: первая башня — первый множитель. Тест П2 проверяет и «7 × 8», и «8 × 7». |
| 9 | 24 побеждён лучом 4 × 6, а волна задумывала 3 × 8 | Засчитывается карточке 4x6; на итогах «24 можно было победить ещё лучом 3 × 8». |
| 10 | Мелкий текст на 1024×600 (`s ≈ 0,5`) | Подписи не мельче 22 px (`max(40, 22/s)` ед.), числа врагов ≈ 20 px; есть «Крупный шрифт». Раскладки рассчитаны на плашку 320 × 66 ед. Подпись «40 × 9 = 360» на земле 6 в крупном шрифте может задеть соседнюю — допустимо, решатель таких лучей не предлагает. |
| 11 | Уход с уровня посреди волны и перезагрузка | Уровень не засчитывается и не сохраняется; лимит дня считается по завершённым уровням. |
| 12 | Боссы на одной дорожке с обычными: лучи обычных врагов «отнимают» у босса | Решатель проверяет всю волну симуляцией; на уровнях с боссом волна строится вокруг свиты (части разрезания), лишние числа — только если решение есть. Ребёнок может ошибиться порядком — это и есть учебная задача, подсказка-путь показывает начало. |
| 13 | Два босса разных карточек мешают друг другу | `b2` — только два босса одной карточки. |
| 14 | Земля 5 требует 33 карточки с победой «в делении» | Это 3–5 дней игры; если окажется долго — снизить до «любые 25 из 33» (одна константа `LAND5_NEED`). |
| 15 | Конфликт сохранений с двух устройств (db) | Выигрывает больший `updatedAt`; посреди уровня снимок не применяется к экрану. |
| 16 | 60 кадров на планшете | Статический фон в кэш-холсте, без `shadowBlur`, ≤ 12 врагов и ≤ 8 лучей, `dpr ≤ 2`. |
| 17 | Перо XP-PEN: «зависание» над экраном и долгий нажим | Учитываются только `pointerdown/move/up` с `buttons > 0` или касанием; `contextmenu` отменён; порог перетаскивания 12 px. |
